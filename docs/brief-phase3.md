## 1. 头号任务：丝滑（用户原话：“有的时候会显得很卡，不丝滑”）

一本讲动效的图鉴自己卡顿，是最致命的问题。这一项**必须用数据说话**，不能凭感觉。

### 先测量，再动手
- 用 Chrome DevTools Protocol（可以写一个 Node 或 Python 脚本，用 headless Chrome 的 `--remote-debugging-port`，或者 puppeteer-core 指向本机 Chrome）录制性能追踪：
  - 从首屏匀速滚动到页底，记录 **帧率、掉帧数、长任务（>50ms）、强制同步布局、重绘面积**
  - 鼠标在首屏、光标展厅、着色器展厅连续移动时的帧率
  - 连续触发爆炸、长按充能时的帧率
- 把**优化前**的数字记下来，优化完再测一遍，写进报告做对比

### 美术总监的怀疑清单（逐条验证，是就修，不是就在报告里说明）
1. **常驻的 requestAnimationFrame 循环太多**：首屏视差、警戒带、各展品的 tick，不在屏幕里也在每帧跑。应合并成一个调度器，展厅离开视口就暂停
2. **每帧读布局**：循环里调用 `getBoundingClientRect` / `offsetWidth` 又写样式，造成布局抖动。缓存尺寸，只在 resize 时更新
3. **昂贵的绘制属性在动**：导览员带 `filter: drop-shadow` 还在视差移动；大面积 `box-shadow`、`mix-blend-mode`、`backdrop-filter`、网点背景在滚动时反复重绘。能烘焙进图片的就烘焙（比如把硬投影直接画进导览员 PNG），动画只动 `transform` 和 `opacity`
4. **canvas 和 WebGL 分辨率**：高 DPI 屏幕上画布按 3 倍像素渲染，应限制 `devicePixelRatio` 上限（例如 2，粒子类可以 1.5），不在视口时停止绘制
5. **滚动监听**：没有 `passive: true`、每次滚动都做重计算的，改为在 rAF 里节流
6. **长页面**：展厅之间用 `content-visibility: auto` 加合适的 `contain-intrinsic-size`，离屏的展厅不参与渲染
7. **图片解码**：大图在进入视口时解码导致卡顿，用 `decoding="async"`、提前 `img.decode()`，尺寸给对
8. **音效**：41 个音频是否在首屏一次性解码，阻塞主线程？应在首次交互后再懒加载解码
9. **字体**：字体切换导致的重排（FOUT），检查 `font-display` 和预加载

验收标准：桌面滚动全程 **平均 ≥ 58fps、没有超过 100ms 的长任务**；鼠标交互时 ≥ 55fps。在报告里给出前后对比表。

## 3. 新展厅 Hall 07：节奏 Timing（美术总监最想加的）

这本图鉴的真正用途，是让用户能把手感说出来：“慢一点”“弹一点”“再干脆一点”。而这些词背后是**缓动和时长**，现在恰恰没有展品讲它。新增：

- **缓动曲线 Easing**：同一个方块用 linear / ease-out / ease-in-out / 回弹 back / 弹跳 bounce 并排跑，旁边实时画出曲线，小球沿曲线走。用户可以拖曲线的两个控制点自定义（cubic-bezier），口令里带上曲线数值
- **弹簧物理 Spring**：调刚度和阻尼，看同一个卡片从“软糯”到“干脆”到“果冻”的变化
- **时长 Duration**：100ms / 300ms / 800ms 三个并排对比，让人感受“多快算快”
- **错落节奏 Stagger**：一排卡片依次进场，调间隔和方向（从左、从中间、随机）

## 4. 口令能“读回来”

现在口令只能复制出去。加一个**口令输入框**（放在顶部导航或收藏页）：把一句口令粘回来，页面自动跳到那件展品，并把参数恢复成口令里的值。这样用户和开发者之间可以来回传口令。

## 5. 按“感觉”找展品

在收藏页加一个**感觉索引**：用一组标签筛选展品，例如 弹 / 顺 / 炸 / 冷 / 酷 / 安静 / 有重量 / 轻飘。每件展品标 1～3 个标签。用户不知道名字时，可以从感觉找过去。
