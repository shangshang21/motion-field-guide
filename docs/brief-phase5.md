# 施工说明书 · 第五期（给 Codex）：做减法与体检

前四期说明书的标准和约束全部有效。**这一期不加新展品、不加新功能。** 四期下来功能很全，但美术总监发现页面在变挤：每张卡片底部叠了“分享/代码”一行、“A/B 对比”一行、再加标题和标签，视觉噪音越来越多。第一次来的访客会被八个展厅、播放控制台、A/B、口令一起砸晕。

## 1. 卡片瘦身（最重要）

- 每张卡片的工具（复制口令、分享、代码、A/B、讲解）合并成**一条紧凑的工具栏**，或收进一个“工具”按钮里，默认只露出最常用的一两个
- 目标：卡片的视觉重心回到**演示本身**，工具不抢戏
- 对照第一期验收过的按钮展厅卡片（干净的三段式：编号条 / 演示区 / 名字），新旧卡片要统一回这个节奏
- 手机上的导览员对话框不要遮住展厅大标题和正在演示的内容

## 2. 第一次来的引导

- 第一次访问时，导览员用 3～4 句话、不超过 30 秒带一遍：这是什么、怎么玩、口令是干嘛的。可以跳过，看过一次就不再出现（本地记住）
- 不要做成遮罩加箭头的老式新手教程，要像游戏里 NPC 打招呼

## 3. 跨浏览器体检

- 用 Playwright（可以 `npx playwright install webkit firefox`，装在项目外或 devDependency 都行，但网站本身仍不需要构建）在 **WebKit（Safari 内核）和 Firefox** 里跑一遍：首屏、每个展厅、音效、着色器、手势
- 修掉发现的问题；实在修不了的写进报告，并保证有降级

## 4. 首次加载速度

- 用 Lighthouse（本地 Chrome，`npx lighthouse`）测手机模式的首屏加载，目标：性能分 ≥ 90，首屏大图和字体不拖后腿
- 记录优化前后分数

## 5. 无障碍基本功

- 所有按钮能用键盘操作，有清楚的焦点样式
- 文字对比度达标（尤其是灰色小字和橙底白字）
- 图片有 alt，演示区有简短的屏幕阅读器说明

## 6. 更新 README

README 是给不懂前端的人看的拆解文档（见现有内容的写法和比喻风格）。把第一到第四期新增的东西补进去：音效来源、性能优化的前后对比（用比喻讲清楚为什么会卡）、节奏展厅、口令读回、A/B、慢放、分享链接。截图换成最新的。保持“每个技术点配一个生活比喻”的风格。
